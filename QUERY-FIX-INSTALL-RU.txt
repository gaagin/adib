ADIB ONLINE 1.1.64 — COST CONTROL V3

Только онлайн-сервер. Дизайн, Windows 1.1.62 и Android 2.5.70 не изменены.

Что исправлено:
1) Общий кеш комментариев на задачу для chat-threads, comment-notifications и task-comments, включая пустые ответы и параллельные чтения.
2) Обзор чата/уведомления: кеш 5 минут. Чтение конкретной открытой переписки: кеш 30 секунд. После отправки комментарий сразу добавляется в существующий кеш; отправка не блокируется. Первая проверка всех задач по-прежнему требует чтений Notion; не обещается один запрос на весь список.
3) Ошибки чтения комментариев: повтор через 5–30 минут. Старые кешированные комментарии сохраняются; ответы помечаются stale/partial. Существующая проверка доступа выполняется до чтения кеша.
4) Таймер работы: чтение сохранённого состояния не обращается к Notion при нормальном прогретом кеше. Итог пишется только после подтверждения; одинаковый подтверждённый итог не пишется повторно. Неудачные записи остаются dirty с паузой 1–30 минут, сохраняемой на диске. При новом итоге разрешена новая попытка.
5) Pomodoro: сохранено редкое обнаружение активных отчётов (5 минут); GET состояния обслуживается из локального сохранённого состояния между проверками. Команды Pomodoro для задач продолжают читать/писать Notion для сохранения синхронизации; глобальный Pomodoro работает локально на сервере.
6) Все ограничения snapshot/realtime из v2 сохранены: фоновые сканы 5 минут, ручные повторные сканы минимум 1 минута при валидном кеше, записи не задерживаются.

Проверка выкладки:
/version.json -> queryFixBuild: 1.1.64-cost-control-v3-auto-countdown-v4
/api/health -> та же метка. queryMetrics.notionApiAttempts считает все фактические вызовы транспорта Notion (включая retry), commentReadAttempts — чтение комментариев, queryAttempts — запросы источников, otherReadAttempts — прочие чтения, writeAttempts — записи. notionQueries/notionWrites — старые логические счётчики; они не равны фактическим попыткам. commentCache/authorCache — попадания и промахи кеша.
Счётчики сбрасываются после перезапуска. Кеш комментариев в памяти процесса также сбрасывается. При нескольких репликах у каждой свой кеш и счётчики. При проверке сначала дождитесь первоначального прогрева, затем сравнивайте прирост.
HTTP Requests в Railway продолжают расти: старые клиенты опрашивают таймеры; это не означает обращение к Notion на каждом HTTP-вызове. Это дополнение не уменьшает существующую частоту HTTP-опроса таймера; маленькое окно не добавляет второго опроса.
Изменения напрямую в Notion видны с задержкой (обзор/уведомления до следующей пятиминутной проверки; открытая переписка — по запросу клиента после истечения 30 секунд). При сбоях задержка дольше.
