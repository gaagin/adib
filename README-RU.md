# ADIB Online 1.1.41 — полный серверный пакет

Это полный набор исходников сервера и веб-интерфейса, а не патч. Node.js 22+ (рекомендуется Node.js 24). Runtime-зависимостей npm нет. Windows EXE и Android в пакет не входят.

## Обновление существующего сервера / Railway

1. Остановите приложение и сохраните резервную копию исходников, `.env` и постоянных данных.
2. Скопируйте содержимое этой папки в корень серверного проекта: `server.js`, `package.json`, веб-файлы, `icons`, серверные модули и остальные файлы пакета.
3. **Сохраните свою `.env`, переменные Railway, папки данных и подключённые тома. Не удаляйте существующие данные и не заменяйте токены пустыми примерами.** Архив не содержит ваших ключей и данных.
4. В Railway используйте Dockerfile из пакета или Node.js 22/24. Команда запуска: `npm start`. Healthcheck: `/api/health`. Порт берётся из `PORT`.
5. Перезапустите / выполните redeploy. Откройте `/version.json`: версия должна быть `1.1.41`.
6. Откройте сайт с обновлением без кэша (`Ctrl+F5`). В статусе календаря должна появиться надпись «календарь 1.1.41». Кнопка «Обновить» повторно проверяет поддержку интервалов.
7. Если Windows работает через этот сервер, после обновления сервера примените Windows-патч 1.1.41 и полностью перезапустите Windows-приложение.

Прямое подключение Windows к Notion использует встроенный API и не требует этого сервера.

## Новый запуск

- `npm ci` (или сразу `npm start`, зависимости отсутствуют).
- Скопируйте `.env.example` в `.env` и задайте `NOTION_TOKEN` приватно, либо используйте переменные среды.
- Сохраните нужные `*_DATA_SOURCE_ID` / `*_DATABASE_ID` и другие переменные из вашей существующей конфигурации.
- Интеграции Notion нужен доступ к используемым базам. Не публикуйте токен в репозитории или браузере.
- Пример локального запуска: `npm start`, затем `http://localhost:3000`.
- При открытом размещении сохраните принятую у вас защиту доступа к серверу; этот пакет не добавляет новую систему авторизации.

## Постоянное хранение

Существующие настройки пути имеют приоритет. По умолчанию служебные данные плана, истории и Pomodoro сохраняются в `data` рядом с сервером. На хостинге подключите постоянный том или задайте `TASK_MANAGEMENT_FILE`, `POMODORO_STATE_FILE`, `COMPLETION_HISTORY_FILE` и, при использовании сохранённого снимка, `SNAPSHOT_RAW_CACHE_FILE` внутри постоянного тома. Не используйте пустую новую папку вместо старых данных при обновлении.

## Исправления календаря

- Клик по карточке открывает обычные свойства задачи, даже если API проверки интервалов временно недоступен.
- В часовой сетке переносится тело карточки; верхний край меняет начало, нижний — окончание. Шаг 15 минут.
- Короткие 15-минутные карточки сохраняют область тела между зонами изменения краёв.
- Если сервер не подтвердил интервалы, появляется понятное предупреждение: свойства доступны, небезопасная запись времени не выполняется.
- Окончание интервала читается и сохраняется в `Tarix.start/end`; оценка и статистика Pomodoro не меняются.
- Все скрипты и стили полного интерфейса теперь выдаются реальными HTTP-маршрутами с правильными типами и безопасным списком публичных файлов.
- Календарные ресурсы имеют версию в URL, выдаются без старого кэша; service worker обновлён.
- Линия текущего времени сохранена, обновляется отдельно от карточек.
