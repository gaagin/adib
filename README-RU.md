# ADIB Online 1.1.42 — полный серверный пакет

Полные исходники сервера и веб-интерфейса, не патч. Node.js 22+ (рекомендуется 24). Runtime-зависимостей npm нет. Windows EXE и Android в этот пакет не входят.

## Обновление существующего сервера / Railway

1. Сохраните резервную копию исходников, `.env` и постоянных данных.
2. Замените исходники проекта содержимым этой папки, включая новые `network-clock-server.js` и `zoned-time.js`.
3. **Сохраните свою `.env`, переменные Railway, папки данных и подключённые тома. Не заменяйте токены пустыми примерами.** Архив не содержит ваших ключей и данных.
4. Задайте `ADIB_TIME_ZONE=Asia/Baku` либо другой нужный IANA-часовой пояс. Без переменной используется `Asia/Baku`, независимо от настроек компьютера и сервера.
5. В Railway используйте Dockerfile из пакета или Node.js 22/24. Команда запуска `npm start`; healthcheck `/api/health`; порт из `PORT`.
6. Выполните redeploy / перезапуск. В `/version.json` должна быть версия `1.1.42`. В `/api/time` после успешной сверки — `trusted: true`, `policy: "network-only"`, нужный `timeZone`.
7. Обновите страницу без кэша (`Ctrl+F5`). В календаре должна быть версия `1.1.42` и надпись «Сетевое время · ЧЧ:ММ · Asia/Baku».

## Сетевые часы — без времени компьютера

- Сервер получает время по HTTPS из заголовка Date источника `www.cloudflare.com`; резервный источник — `www.microsoft.com`. Для исходящих HTTPS-запросов нужен доступ к этим адресам. Это сетевые HTTPS-часы, не высокоточный NTP-клиент; точность ограничена секундным заголовком и задержками сети.
- Браузер использует `/api/time`. Текущая дата, «Сегодня», линия текущего времени и календарные поля используют часовой пояс приложения, а не операционной системы пользователя.
- После подтверждения время продвигается монотонным таймером `performance.now()`. Изменение даты/часов компьютера не сдвигает календарь.
- При потере связи уже открытая сессия продолжает отсчёт от последней сетевой сверки, с предупреждением. Сверка выполняется регулярно; максимальная давность подтверждения — 24 часа.
- При первом запуске без подтверждённого времени (или после истечения подтверждения) приложение показывает экран ожидания с кнопкой «Повторить». Подстановка времени компьютера отключена. Перезагрузка браузера без доступа к источнику не восстанавливает часы из локальных настроек.
- Кнопки «Обновить» и «Сверить сейчас» повторяют запрос. Сервер ограничивает частоту запросов к источнику времени.
- Часовые задачи сохраняются как UTC ISO и показываются в часовом поясе приложения. Задачи только с датой сохраняются без преобразования в UTC.
- Уже сохранённые ошибочные даты задач автоматически не переписываются: проверьте их отдельно.

## Новый запуск

- `npm ci` (или сразу `npm start`, зависимости отсутствуют).
- Скопируйте `.env.example` в `.env`, задайте `NOTION_TOKEN` приватно или через переменные среды.
- Сохраните нужные `*_DATA_SOURCE_ID` / `*_DATABASE_ID` и другие параметры вашей конфигурации.
- Интеграции Notion нужен доступ к базам. Не публикуйте токены в репозитории или браузере.
- Локальный запуск: `npm start`, затем `http://localhost:3000`.
- При открытом размещении сохраните принятую у вас защиту доступа: пакет не добавляет новую систему авторизации.

## Постоянное хранение

Существующие настройки пути имеют приоритет. По умолчанию служебные данные плана, истории и Pomodoro сохраняются в `data` рядом с сервером. На хостинге подключите постоянный том или задайте `TASK_MANAGEMENT_FILE`, `POMODORO_STATE_FILE`, `COMPLETION_HISTORY_FILE` и при необходимости `SNAPSHOT_RAW_CACHE_FILE` внутри постоянного тома. Не подменяйте старое хранилище пустой папкой.

## Календарь

Сохранены исправления клика по карточке, переноса тела карточки, изменения начала верхним краем и окончания нижним краем (шаг 15 минут). Интервалы сохраняются в `Tarix.start/end`, не меняя оценку и статистику Pomodoro. Если сервер не подтверждает поддержку интервалов, свойства доступны, но небезопасная запись времени блокируется. Красная линия времени обновляется отдельно от карточек.

## Проверки выпуска

`npm test`: 19 тестов, 0 ошибок. Проверены HTTP-ресурсы и приватные пути, API интервалов с подставным Notion, сетевой источник и резерв, отсутствие локального fallback, ограниченный отсчёт без сети и преобразования часового пояса.

Полный веб-интерфейс проверен в Chromium на Linux с намеренно неверной датой компьютера (2001 год), скачком локальных часов и часовым поясом Pacific/Honolulu. Сетевое время в фикстуре 13:18 Asia/Baku отображается правильно. Проверены свойства, перенос, изменение длительности, неделя, смена сетевого дня, потеря связи, первый запуск без сети и повторная сверка. Светлая/тёмная темы и мобильный экран осмотрены. Реальный запрос сервера к Cloudflare отдельно вернул подтверждённое время. 13:18 — только тестовая фикстура, не фиксированное время в приложении.

Живые записи в Notion, сервер пользователя и физический Windows EXE не проверялись. Этот архив автоматически не развёртывается на вашем сервере.
